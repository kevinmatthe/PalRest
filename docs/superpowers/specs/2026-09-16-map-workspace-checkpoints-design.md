# 地图工作台与玩家变化观察：设计草案

状态：用户已认可设计。阶段 A 已实现并完成验证；阶段 B 已实现并完成真实存档与回归验证；阶段 C 是后续范围，不能视为已实现。

## 目标

将地图作为 Playguard 的主要入口，让用户在同一视图中理解“谁在哪里、最近发生了什么、这次游玩有什么进展”，并能平滑回看历史。保留现有防沉迷、管理和统计能力，新增的观察任务不阻塞 Guard 关键路径。

## 代码现状与边界

- `webui/src/main.tsx` 当前分为总览、分析、实时地图、时间轴、策略管理，切换实时与历史会切换组件。
- `LiveMap.tsx` 每秒请求位置接口，但后端位置来自 `/players` 的实际采样；示例配置是 30 秒。刷新时会清空并重建玩家标记。
- `PlayerTimeline.tsx` / `mapPlayback.ts` 已有逐点播放、按时间间隔播放和倍速。`TimelineMap.tsx` 已有呼吸效果，但焦点随离散样本重建，自动平移关闭动画。
- 已有行为分析可计算静止、局部活动、赶路、活动半径、路径和地点停留。它们是基于采样的估计。
- Save Worker 已提取玩家等级、经验、生命值、公会与据点，尚未输出帕鲁拥有数量和传送点解锁集合。当前 Worker 对 Players 文件做指纹计算，但玩家主体数据从 Level.sav 提取。
- 仓库内 PalworldSaveTools 有 OwnerPlayerUId、玩家帕鲁容器及 PalCaptureCount、PaldeckUnlockFlag 的处理线索。它们不能代替当前服务器版本的存档验证；本次检查尚未确认玩家传送点解锁字段。
- 旧设计排除了详细帕鲁集合；本次建议明确扩展为统计和用于差分的稳定 ID 集合，不引入背包编辑器。

## 路线选择

1. **推荐：统一地图工作台，接入 checkpoint 变化流。** 先完成可独立验收的地图交互，再接真实玩家进度；统一选择状态和时间语义。
2. 仅改现有页面视觉。交付较快，但实时与历史依然割裂，无法解决“最近做了什么”。
3. 先扩大采集和统计范围。数据基础先完善，但用户最期待的地图体验会较晚出现。

## 地图与交互

桌面地图占满主视口并作为工作区底层。顶部是紧凑导航和服务状态；右侧是可折叠玩家列表；底部是实时/历史共用的时间控制条。历史播放时可展开事件刻度，详细统计与管理从明确入口打开。

选择玩家后，地图与列表同步高亮；定位和持续跟随是两个动作。用户手动拖地图即暂停跟随，通过按钮恢复，轮询不夺回镜头。浮窗显示玩家名、等级、最近位置更新时间和近期变化，呼吸效果仅用于当前选中点。历史浮窗明确写“回放位置”，不冒充当前位置。

默认地图图层保留玩家与必要地形；传送点、据点、停留热度、轨迹可分别开关。搜索、列表滚动、浮窗点击不穿透到地图。移动端使用底部抽屉并与播放控制避让；支持键盘操作和减少动态效果设置。

全局持有选中玩家、实时/历史模式、回放时间、跟随状态、图层设置和面板开合状态。地图实例持续存在，切换模式保留视角；实时更新仍进入缓存，但历史模式的画面只由回放时间决定。

## 平滑移动与回放

实时标记以稳定玩家 ID 复用。只有更新的观测到来才移动，普通位置变化采用约 300–700ms 的短过渡；重复响应不重复启动动画。位置过期时保留最后观测并标记陈旧，不预测玩家继续移动。

历史使用连续时间游标驱动标记、轨迹进度和浮窗，动画帧插值发生在两个有效样本之间。倍速影响播放时钟；拖动时间轴直接定位；暂停停止推进。插值点属于视觉表达，不写回数据库、不参与距离和速度计算。

跨轨迹段、服务器重启、未知区间和疑似传送不画连续移动。以淡出/淡入或明确的跳跃标识表达，并展示缺口。长时间缺口可显式跳过，不把缺口压缩后呈现为持续活动。镜头仅在启用跟随且焦点越过安全区域时柔和平移。

## Checkpoint 与差分

Checkpoint 是某个来源的一次成功观察，不要求位置与存档同步采集：

- 快通道沿用 REST 采样，记录位置、在线状态和可用等级等。
- 慢通道沿用独立的存档导入，在文件内容变化且可稳定读取时解析玩家进度。解析并发限制为一，不把大存档解析接到每次位置轮询中。
- 同一张玩家卡可以汇总多来源字段，但每个字段保留自己的来源与观测时间；合并显示不生成新的虚假观测。

Checkpoint 保存稳定玩家身份、世界身份、来源、来源时间/采集时间、schema 版本、来源指纹和字段有效性。具体指标采用明确类型；缺失、不支持和解析失败均不能写成 0。

仅对同一玩家、同一世界、兼容口径且时间递增的快照比较。首次出现只建立基线；乱序快照可留存，但不回退当前值。重复快照不重复生成事件。指标基线变化或存档回档作为边界处理，不生成负捕获数等行为描述。

在同一事务中提交快照与差分，事件以快照对、指标和规则版本去重。保留原值、新值、变化量、区间起止、来源证据和规则版本，使规则可解释、可重算。REST 事件接入现有时间线语义，避免重复生成等级变化。

存档需取稳定副本并检查读取期间是否变化；跨文件一致性未确认时，该快照不参与变化推断。身份映射不确定时不依名字合并玩家。

## 第一批指标口径

| 指标 | 口径与展示 | 数据要求 |
| --- | --- | --- |
| 拥有帕鲁数 | 属于玩家的有效帕鲁实例去重计数；不能只数地图上加载的 actor，也不把全公会帕鲁算给每个成员 | 核实归属字段及容器关系；无法可靠归属的单独标记 |
| 累计捕获记录 | 保存来源计数及其差值，和拥有数量分开 | 验证当前版本 PalCaptureCount 的结构和含义 |
| 图鉴进度 | 已确认的解锁种类集合及新增 ID，不直接以数组长度当解锁数量 | 核实解锁标志取值与物种 ID |
| 已解锁传送点 | 本草案暂将“解锁点”解释为传送点；保存 ID 集合并做集合差分 | 验证玩家存档字段；未确认时显示不支持，不能以经过地标代替解锁 |
| 等级与经验 | 来源明确的当前值、净变化和增长曲线 | 复用现有字段，并区分 REST 和存档观测时间 |
| 地点停留与移动 | 据点附近停留、活动范围、采样路径、疑似传送 | 复用现有分析，标明覆盖率与未知区间 |

不能可靠支持的指标保留能力状态，不给出伪造的演示值。上线字段需通过当前服务器的代表性存档和真实前后变化校验。

## 事实、推断与有趣的呈现

第一层是可以复核的变化：例如“20:10–20:15 拥有帕鲁 42 → 45，净增 3”“新增解锁 2 个传送点”。存档差分仅支持时间区间，不伪造精确发生秒数或地图坐标。

第二层是有依据的推断：例如“这段时间可能以探索为主”，展示新增解锁、活动范围和轨迹覆盖作为理由。使用规则和证据说明，不输出没有校准依据的概率。

拥有数增加不等于捕获；减少也不等于死亡。没有额外证据时，不能区分交易、孵化、浓缩、出售等原因。静止不等于挂机，附近停留不等于完成对应活动。推断不参与防沉迷执法。

产品呈现优先做：

- 玩家“本次游玩小结”：已观测时长、等级变化、帕鲁净增、解锁进度、主要停留区域。
- 地图上的足迹与停留热度：使用有效时间加权，避免把采样密度当成活动强度；不称为真实迷雾探索完成率。
- 可点击的变化时间线：有确切地点证据才定位，否则仅定位到时间区间。
- 成长曲线与里程碑：在可比较的 checkpoint 上计算，不跨未知数据补零。

第一期不引入大模型作为事实判断依赖。后续若增加自然语言总结，只总结有证据的事件。

## 分期交付与验收

### A：地图工作台与连续回放

复用 Leaflet、地图瓦片、已有 API 与时间线，抽出共用地图生命周期和标记控制。默认进入地图；右侧玩家列表可收起；选择、跟随、历史切换和底部时间轴贯通。

验收：轮询不重建全部 marker；实时/历史切换保留视角；新实时数据不改变历史画面；播放可暂停、拖动、变速；未知区间和传送不补造轨迹；桌面和移动端控件不遮挡关键交互；减少动态效果设置生效。

### B：玩家进度 checkpoint 与变化流

先验证字段和口径，再扩展 Worker 契约、数据库与查询 API。按已验证能力上线帕鲁统计和解锁集合，与地图详情和事件时间线联动。保留现有历史和 API 的兼容性；旧记录没有新字段时显示未采集。

验收：首次基线无虚假新增；重复导入无重复事件；缺失值无虚假减少；回档、乱序、跨世界、身份不明和不一致文件不会生成误导变化；数量与集合差分通过代表性存档验证；Worker 失败不影响 Guard。

### C：有证据的游玩摘要

在 B 的有效变化上组合游玩小结、成长趋势和探索活动推断。将事实、推断、时间覆盖与数据新鲜度同时呈现。

验收：每条推断能展开证据；样本不足时不下结论；摘要的数字能回溯到快照或现有观测；不把已观测路径当作完整行程。

## 评审范围

建议采用路线 1，先实施 A，同时为 B 做当前服务器存档字段验证。本草案对“解锁点=传送点”以及“帕鲁数量同时区分拥有与捕获记录”采用明确默认口径，可在实现前根据用户意图调整。
